# Сценарии и сдача

Начинайте каждый сценарий с новой сессии. Допустимы другие формулировки и порядок равнозначных вопросов. Отвечайте по карточке фактов, оставляя неизвестные значения неизвестными. Не пропускайте ошибки, повторные вызовы и медленные шаги. Проект сверяется по интерфейсу, текущему JSON, открытому в draw.io файлу и журналу, а консультация — по содержательному ответу и источникам. Номера внутренних объектов, буквальный текст и порядок ключей не оцениваются отдельно. Закрытый набор и тарифный снимок фиксируются организаторами до сравнения.

## Сквозные проверки

| ID | Действия и проверка |
| --- | --- |
| U01 | Два хранилища, двусторонний обмен SFTP по расписанию, общая видимость и одинаковые проверки, людей нет. Ожидать два правила PULL → PUSH в разных направлениях и два технических пользователя. |
| U02 | В отдельных сессиях сравнить два отдела с одинаковыми проверками и раздельной видимостью (2 правила, число людей уточнить) и общий доступ с проверкой размера на отправляющем узле и ICAP на принимающем (1 правило). |
| U03 | Выполнить F01. Спросить причину и получателя, сохранив ревизию. Добавить второй офисный сервер UDP 514 → 2 правила. Переименовать его → те же 2 правила и новые подписи. Попросить удалить один сервер → уточнение без изменения. Удалить выбранный → 1 правило. Попросить открыть офисную подсеть → объяснить предел и сохранить корректную ревизию. На каждом допустимом изменении повторить скачивание .drawio и экспорт JSON. `session_id` общий, история и расходы накопительные. |
| U04 | Запрос на три сети → предложить проект для одной пары. В отдельном запуске обе сети открытые → согласовать защищаемую сторону. При «не знаю» оставить предварительный статус. |
| U05 | Выполнить F07. Проверить увеличение и вписывание. Открыть экспорт в draw.io, изменить подпись и положение блока. Сопоставить правила с таблицей и JSON. Проверить, что ссылки о возможностях ведут к нужному разделу или странице. |
| U06 | Проект с уточнениями и контролируемым повтором. Сверить журнал эмбеддингов, вспомогательных вызовов и повторов с суммой сессии. Проверить повторное получение usage, видимый неизвестный расход, отдельную индексацию, допустимость всех тарифов и время до полной отрисовки. |
