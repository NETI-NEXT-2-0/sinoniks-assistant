# Первый запрос и неполные требования — задача 03

## Поведение

Для двух открытых сетей приложение спрашивает, какую считать защищаемой
в данном проекте. Выбор сохраняется в optional `protected_network_id` контракта
v3, адресном ответе и редакторе требований. Это допущение о размещении,
а не изменение фактического `trust=open`. При неизвестном выборе результат
остаётся предварительным; ответ «Не знаю» сохраняется как `user_unknown`.
Противоречие с единственной закрытой сетью требует уточнения.

Новое поле проверяется по существующим сетям и переназначается вместе с ID
модельных сущностей. Редактор и сервер сохраняют происхождение изменения.
Отсутствующее значение без корневой заметки не добавляется в сериализацию:
старые command hashes и сохранённые архивы остаются прежними. Миграции БД нет.
Если корневая заметка существует, `null` сохраняется, чтобы её путь разрешался.

Вопрос о декоративном названии потока больше не блокирует расчёт. Неизвестный
порт остаётся `null`; вопрос о нём необязательный. Протокол, направления,
способы передачи файлов, проверки и доступ уточняются по существующим полям.
«Другое» и исходное пожелание используют механизм задачи 10.

Валидное предложение модели с более чем двумя сетями не обрезается и не
записывается: приложение спрашивает, какую пару рассмотреть. Ответ не требует
дополнительного repair-вызова, usage исходного вызова сохраняется. Остальные
ошибки контракта и нарушения происхождения по-прежнему отклоняются. Предыдущая
хорошая ревизия не меняется. Смешанное описание сохраняет допустимые потоки,
а неподдерживаемое требование — отдельно в `requests_for_vendor`.

## Проверки и границы

- `test_protected_network_choice.py`: обе открытые сети, явный выбор,
  неизвестное, round-trip, старый хеш, переназначение ID, неверная ссылка.
- `test_incomplete_scenarios.py`: синтетические N01, N05 и смешанная задача;
  неизвестные не превращаются в выдуманные методы, проверки или пользователей.
  После уточнения N05 остаются журналы, получаются два правила и один пользователь.
- `integration/test_open_network_projects.py`: настоящая PostgreSQL, сохранение
  «Не знаю» и выбора без вызова модели, idempotency, старые байты артефактов,
  переназначение ID и сохранение прежней ревизии при трёх сетях.
- `scripts/ci/browser_incomplete_requirements.py`: пять независимых сессий,
  реальные формы/кнопки, редактор, reload, N01/N05/U04 и смешанный запрос.
  Только явно подтверждённый loopback-фикстур: переменные
  `PARTNER_DIAGRAM_FIXTURE_CONFIRMED=1`,
  `PARTNER_DIAGRAM_BROWSER_ACCOUNT_FILE`, при необходимости `CHROMIUM_PATH`.

Фикстур распознаёт зарезервированные синтетические маркеры. Это проверка
сохранения, вычисления и интерфейса, а не оценка понимания свободного русского
описания настоящей моделью. Такая оценка остаётся задачей 12. Платных вызовов
и изменений embeddings нет.

Полный `./init.sh check`: 509 backend и 18 frontend, Ruff, mypy 93 модуля,
TypeScript и production build прошли. Результат PostgreSQL и браузера также
зафиксирован в `progress.md`; облачный CI при прямом push не объявляется зелёным.
