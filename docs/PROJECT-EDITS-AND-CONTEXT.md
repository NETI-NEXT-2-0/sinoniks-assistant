# Адресные правки и контекст большого проекта

Два связанных P0: повторная генерация всего Requirements v3 для малой правки
и ограничение сериализованного контекста 32000 символов.

## Контракт изменения

Сохранённый v3 редактируется через design_patch.operations: add/update/remove,
коллекция и точный ID сущности, values только изменённых полей. Отдельный update
для project допускает только поля инженерных условий и заметок. До 64 операций;
новый проект по-прежнему извлекается целиком. Старые полные предложения совместимы.

База берётся из захваченного сервером RunDesignContext, не из ответа модели.
Патч применяется к копии атомарно; полная Requirements19 проверяет ссылки,
сети и типы. Существующий путь завершения проверяет владельца и актуальность
ревизии, назначает provenance и ID новых объектов, пересчитывает артефакты.
Модель не может менять ID, импортные метаданные, sources и схему документа.
Удаление используемого объекта без согласованных изменений ссылок отклоняется.

## Контекст

Модели передаётся компактный вид Requirements19 без значений по умолчанию,
provenance и неизменяемых импортных метаданных. Полная база остаётся на сервере.
Значимые различия checks=null/[] сохраняются. Из истории удаляются повторные
целые пары; текущий запрос сохраняется дословно. Поля проекта не обрезаются.

Для объявленного окна модели учитывается резерв выхода и консервативная
оценка UTF-8 bytes + 64 на сообщение. Абсолютный предел 256000 UTF-8 байт (с запасом на сообщения)
ограничивает расход/размер и остаётся ниже порога тарифного повышения272k; при неизвестном окне остаётся прежний 32000.
Увеличение предела дополняет сокращение дублей, не заменяет его. Если полный
компактный проект не помещается, вызов модели не совершается.

## Проверки

Регрессии патча и контекста проверяются отдельно. Сквозное сохранение,
пересчёт, архив и конфликт ревизии проверяются на отдельной PostgreSQL.
Проверены добавление/переименование/удаление, атомарность ошибочного пакета,
запрет перезаписи конкурентной ручной версии, сохранность старого draw.io.
Ранняя схема и пакетные уточнения уже в PR27/21/31. На свежей develop
браузер подтвердил «Сохранить и рассчитать»: версия2, одно правило, SVG,
повторное открытие после reload. Платных вызовов для этой проверки не было.

Отдельные регрессии: компактный проект из242систем помещается в прежние
32000 без потери сущностей; более длинный проект использует объявленное окно.
Дубли истории убираются целыми парами. При большом расчёте сохраняются
числа, фактическое размещение и все связи правил с потоками, вместо повторения
полных подробностей каждого правила. Запрос вне окна не доходит до провайдера.
Живой шестишаговый сценарий выполняется после этих изменений.
Текущий статус проверок фиксируется в progress.md и PR.

Пустые nullable name/purpose/policy/details/existing_firewall_name модели
нормализуются в null. Это отсутствие значения, не выдумывание данных.
ID, ссылки, протоколы, числа и обязательные пояснения остаются строгими.
Проверено отдельно для нового полного документа и адресной операции.
