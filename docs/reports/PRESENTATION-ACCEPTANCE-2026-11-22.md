## Основа и условия

Проверка проходит на отдельном VPS-стеке с собственными PostgreSQL, Garage,

Веб-поиск для расширения функций продукта выключен.

Модель — Polza, `openai/gpt-6-luna`, вариант `openai`, без резервного маршрута.
Официальный снимок OpenRouter подтверждает $0.10/$0.50 за миллион входных/выходных
токенов для обычного маршрута. Тариф повышается для очень длинного контекста;
фактические запросы текущего среза существенно ниже порога 272000 входных токенов.

## Проверяемое исправление

Добавлена явная настройка `PARTNER_MODEL_REASONING_EFFORT` с вариантами low,
medium и high. Пустое значение сохраняет прежнее поведение провайдера.
Chat Completions и Responses получают параметр в своих форматах; настройка
и максимальный выход записываются в снимок каждого вызова. Скрытый повтор не
добавляется. На отдельном кандидате проверяется low и запас выхода 6000.

Это гипотеза исправления задержки/обрезания, не доказательство качества:
результаты повторной живой проверки будут добавлены ниже.

Повтор на low/6000: F04 сохранил предварительную версию (32.203 с),
F07 вернул полный JSON, но отклонён валидатором (54.506 с). Ускорение не
подтверждено. В F07 причиной оказался адрес примечания `/flows/<id>/…`
вместо `/flows/<index>/…`. Добавлено преобразование только однозначного ID
существующей сущности при совпадающем target_id. Значения, смысл unknown и
все ссылки по-прежнему проверяет Requirements19. Исходный ответ F07 после
преобразования проходит ту же полную проверку: две сети, три потока.
Регрессии проверяют эквивалентность, идемпотентность и сохранение отказов для
неизвестных ID, чужого target_id, несуществующих полей и unknown на известном
значении. Живой повтор после этого исправления ещё требуется.
[Описание reasoning](https://developers.openai.com/api/docs/guides/reasoning?api-mode=chat),
[параметры OpenRouter](https://github.com/OpenRouterTeam/docs/blob/main/api_reference/parameters.mdx).

## Автоматические проверки и артефакты

Исходный кандидат: 676 unit и 260 PostgreSQL (без storage/parser), Ruff прошли.
Живые действия выполняются через настоящий браузер; фиксируется POST полного
рендеринга, не первый токен. Сохраняются исходные снимки чата, журнал,
экспертный JSON, draw.io и кадры. Файлы с учётками и сырые диагностические
ответы модели остаются закрытыми и в Git не включаются.

Для презентации готовятся отдельные кадры документов, редактирования копии,
подсветки чувствительных данных, пространств/групп и сравнения обычного читателя
с учеником. На испытательном стенде общее демо-чтение выключено; у двух обычных
аккаунтов различаются только разрешённые материалы. Это реальная проверка ACL,
а не разные ответы, заданные ролям в промпте. Основной сайт сохраняет общий
доступ для презентации, разрешённый владельцем ранее.

## Исправление ручной проверки PDF

На технической презентации из ZIP воспроизведён тупик публикации:
`native_text_order_uncertain` блокировал даже вручную исправленную копию.
Теперь куратор может отдельно подтвердить сверку порядка и смысла с оригиналом.
Подтверждение действует только для проверенной текстовой копии, входит в её
хеш и записывается в аудит; изменение текста сбрасывает флажок в интерфейсе.
Согласование исходных блоков без копии, неявное подтверждение, повреждённый
canonical и несвязанные сноски по-прежнему запрещены. Оригинал и его координаты
не изменяются. Цитаты из копии ссылаются на её символы, а не на выдуманную страницу.
