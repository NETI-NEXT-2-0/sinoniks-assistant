# Обратная связь и образовательные ответы

## Границы работы

Новая задача от 21 ноября. Независимо от диагностики PR18: добровольные
звёзды и комментарий, менеджерский список, компактные источники и новые
материалы. Backend: feedback_routes и отдельный тип product_feedback в существующем
журнале Admission. Изменения схемы БД не нужны.

## Добровольная обратная связь

После первого успешного ответа в чате показывается неблокирующая оценка
1–5. При выборе любой оценки открывается окно
необязательного комментария до 2000 символов. Можно отправить отзыв
с текстом, отправить только оценку или закрыть окно без отправки.
Перед выбором видно, что администратор получит оценку и логин.
Закрытие окна до отправки не сохраняет оценку и позволяет выбрать другую.
Одна отправка на чат; повтор с тем же ID/содержимым идемпотентен.

GET/POST /api/v1/chats/{id}/feedback требует владельца живого чата;
POST дополнительно CSRF/Origin и успешный Run этого пользователя/чата.
GET /api/v1/admin/feedback доступен только менеджерам и возвращает
ограниченные страницы: id, rating, comment, author, created_at.
Идентификаторы чатов/запусков, сообщения, документы и ответы не возвращаются.
Удалённые чаты исключены из выдачи; физическое удаление каскадное.
Старые model_quote/user_submission wishes и JSON-выгрузка сохранены:
вынесены из-под чата в отдельный раздел, не конвертируются в пользовательские звёзды.

## Образовательная часть и ТЗ

Сверен предоставленный владельцем DOCX «Кейс _ АйТиБастион», раздел6.
Сведения о продукте берутся только из предоставленной базы знаний;
внешние источники не расширяют функциональность Синоникса в кейсе.
Для обучения допустимо объяснять документированные возможности и сетевые
термины, разбирать сохранённую архитектуру без изменения проекта.
Общие сетевые справки должны быть обозначены как общие, а не как
доказательство поддержки функции продуктом. Наличие RFC в корпусе не
меняет ограничений версии1.9 или методики расчёта.

Автоматический веб-поиск по вопросам о продукте не включается. Это решение
основано на прямом ограничении ТЗ, а не на отсутствии веб-инструмента.
Улучшение коротких справочных продолжений выполняется отдельно от
проверки цитат/ошибок провайдера коллеги; успешный пустой поиск должен
давать честное недостаточное подтверждение, а транспортный отказ сохраняет
свой технический статус и не выдаётся за отсутствие сведений.

## Короткие продолжения и контекст схемы

Для короткого местоименного вопроса («По какому принципу оно работает?»)
поиск сначала учитывает последний пользовательский вопрос. Случайное
совпадение по общему глаголу не должно вытеснять прежнюю тему. Явный новый
код/номер не наследует старый идентификатор. Есть две синтетические регрессии.
Это улучшение retrieval, а не обход проверки цитат или исправление ответа модели.

Режим «Справка» теперь получает условия и расчёт сохранённой схемы своей
ветки как read-only контекст. Вопрос о протоколе использует фактические
значения схемы; история проектного разговора не отбрасывается только из-за
выбора reference. Поддержан project_explanation при наличии снимка;
предложение design в reference по-прежнему запрещено и провайдером, и
завершающей транзакцией. Проверки цитат не ослаблены.

Источники производного проекта проверяются перед передачей контекста.
Если они отозваны, reference исключает недоступный проект и его историю,
но может ответить на общий учебный вопрос по другим разрешённым материалам.
Ошибки БД, отключённый пользователь и другие отказы не подавляются этим
правилом. Для auto/design прежний отказ от работы с отозванными условиями
сохранён. Проект не изменяется: PostgreSQL-тесты сравнивают ID, хеши
артефактов и байты draw.io до и после вопроса о UDP514, включая v3.
Чужой администратор по-прежнему не получает доступ к чату/запуску.

Полные проверки: 594 backend unit, Ruff/mypy96, lock, 38 настоящих
PostgreSQL-интеграций и 18 frontend, TypeScript/Vite прошли. Браузер отзывов
повторён после перехода на существующий журнал Admission. Новых таблиц,
моделей ORM, миграций и изменений версии схемы БД в итоговом diff нет.
Синтетические проверки не объявляются живой оценкой внешней модели.

## Общая база для презентации — 22 ноября

Диагностика VPS подтвердила: у новой обычной учётки поиск возвращал 0 фрагментов,
хотя в базе сохранены 28 документов и 610 единиц раскрытия. Это отсутствие
назначенного доступа, а не потеря файлов. По явному поручению владельца добавлен
операторский `PARTNER_DEMO_PUBLIC_KNOWLEDGE=true`: любой вошедший пользователь,
включая новую регистрацию, получает чтение опубликованного корпуса и оригиналов.
По умолчанию режим выключен; выключение возвращает обычную политику без массового
изменения grants. Приватные вложения чатов, неопубликованные/удалённые материалы,
редактирование и чужие чаты не открываются. Ограничения чувствительных фрагментов
сохраняются. Оригиналы доступны только по действующей утверждённой версии через
существующую проверку скачивания. Флаг требуется одинаково задать API и исполнителю.

В инструкции модели разделены вопросы о продукте/презентациях и вопросы о текущей
схеме. Сохранённый UDP-пример не должен заменять описание устройства из руководства.
Запрос слайда требует реального источника и проверенного локатора; ASCII-схема
не объявляется слайдом документа. Не добавлялись скрытые повторные платные вызовы.

Проверено на VPS: после включения режима у той же новой обычной учётки
0 → 8 доступных фрагментов на вопрос о работе Синоникса. Скачивание настоящего
утверждённого исходника через публичный HTTPS обычным пользователем прошло
с проверкой размера и SHA-256, без платного вызова модели. API и единственный
исполнитель используют runtime47652bf и одинаковый флаг. Синтетические проверки
подтвердили возврат ограничений при отключении, исключение private/unpublished/
deleted и сохранение запретов чувствительных фрагментов; общий прогон — 251 PG.

Для завершения презентационного режима оператор ставит
`PARTNER_DEMO_PUBLIC_KNOWLEDGE=false` в закрытом окружении и обновляет API,
исполнитель и служебные процессы тем же Compose. Сначала дождаться отсутствия
активных запросов. Выданные общим режимом разрешения не записываются в grants;
поэтому выключение не требует массового удаления разрешений. Существующие
обычные индивидуальные/групповые разрешения продолжают действовать.
