# Развёртывание демонстрации и пилота

## Состояние 22 ноября 2026

На отдельный VPS Ubuntu 24.04 перенесён runtime из `299ac71` (продуктовая основа
PR №34 и подтверждение черновиков уточнений). Основной локальный checkpoint
на 8080 остаётся работающим. Это развёртывание пилота, без release/tag и без
объявления полной конкурсной или промышленной приёмки.

Снимок приложения содержит 3 учётные записи, 28 документов, 610 единиц раскрытия,
45 чатов и 74 сохранённые ревизии проектов. Перенесены оригиналы и производные
материалы: 85 объектов, каждый проверен после записи по SHA-256. Права на
документы и исходники сохранены; регистрация сама по себе не открывает чужие
материалы. Администратор назначает участникам необходимые группы доступа.

Выбран VPS 8 vCPU, 16 ГБ RAM, 150 ГБ диска. Модель работает через Polza,
`openai/gpt-6-luna`, вариант `openai`; эмбеддинги не менялись. Сетевой запрос
к каталогу модели с VPS возвращает HTTP 200, без платной генерации ответа.
Проверка качества генерации на новом хосте отдельно не заявляется.

Внешний HTTPS проверен с доверенной цепочкой сертификата; Chromium подтвердил
вход существующего пользователя, 23 его сохранённых чата, отсутствие page errors
и горизонтального переполнения при 1440/390. Формы дополнительно проверены
на отдельной HTTP-фикстуре: восстановление черновика, зелёное подтверждение,
отсутствие ложного подтверждения при заблокированном storage, отправка ответов.

## Конфигурация

- Снаружи опубликованы только Caddy 80/443 и SSH. PostgreSQL, Garage, Qdrant
  и API доступны внутри Docker. Консоль Hatchet привязана к loopback.
- `PARTNER_ENVIRONMENT=production`; диагностика сырых ответов выключена.
- Регистрация включена. Сессионные cookies Secure/HttpOnly, проверяются Origin
  и CSRF. Обязателен публичный HTTPS origin.
- Стоимость модели учитывается по сохранённому снимку OpenRouter. На VPS
  установлены ограничители: $0.20 за запрос и $2.00 за сутки. Это оценка
  по каталогу, а не гарантия точного рублёвого списания посредника.
- Только один исполнитель задач на базе нового сервера. Старые доставленные
  события не переотправляются; автоматический перехват выключен.
- Своя DNS-зона может обновляться до суток. Для демонстрации допустим временный
  HTTPS hostname, указывающий непосредственно на VPS; при смене hostname
  меняется PUBLIC_ORIGIN, Caddy и перезапускаются API/исполнитель.

Секреты, дамп, объекты, манифесты образов и SSH-ключ находятся только в локальном
закрытом каталоге оператора и на VPS, в Git не публикуются. Адрес/пароли сервера
не являются частью воспроизводимой конфигурации проекта.

## Воспроизводимая подготовка

1. Зафиксировать проверяемую версию Git; выполнить `./init.sh check` и целевые
   PostgreSQL-проверки в отдельной базе.
2. `python scripts/build-candidate.py --output <private-directory> --export`
   собирает runtime и web с полным SHA, сохраняет image ID и SHA-256 архива.
   Исходники должны быть зафиксированы; сценарий не публикует образы/релиз.
3. В новой закрытой папке выполнить `scripts/bootstrap-env.py`, задать
   production origin, модель, тариф и лимиты. Не копировать прежние пароли БД.
4. `python scripts/prepare-pilot.py --revision <full-sha> --check-env`
   создаёт HTTPS Compose. Файл не перезаписывается; API не получает Docker socket.
5. Загрузить образы. Поднять хранилища и Hatchet, выполнить bootstrap Garage
   и Hatchet, восстановить дамп в **новую** базу. Выполнить миграции/провизию.
6. Перенести S3-объекты с проверкой хешей; только затем включить исполнитель,
   ingest и Caddy. Не запускать второй конверсионный координатор.
7. Проверить публичный TLS, `/health/ready`, вход, права на документы,
   сохранённый проект, регистрацию и расходы. При необходимости отдельно
   согласовать платный сценарий; восстановление дампа не является проверкой LLM.

При недоступности registry передавать проверенные образы через SSH и `docker load`.
Сохранять исходные digest образов инфраструктуры в закрытом манифесте переноса.

## Проверки и границы

На продуктовой основе: 657 unit-тестов; после актуализации ожиданий управляемого
восстановления — 246 PostgreSQL-проверок без storage/parser. Сборка React включает
TypeScript typecheck, клиентские тесты выполнены. Изменение тестовых ожиданий
сохраняет проверки неизменности ревизии, расходов и запрета публикации невалидного
ответа модели: управляемое уточнение теперь завершается `succeeded` с
`task_completed=false`, а не красной технической ошибкой.

Не приравнивать это к полной приёмке: нагрузка, независимое внешнее рассмотрение,
полная конвертация новых PDF на VPS, восстановление всех сервисов из резервной
копии и содержательные ответы по каждому конкурсному сценарию требуют отдельных
свидетельств. Точные слайды презентаций остаются ограничением прежнего прогона.

## Резервная копия и завершение демонстрации

Перед сменой версии сохранить PostgreSQL (custom dump) и согласованный комплект
S3-объектов. Проверять восстановление на отдельном экземпляре. Дамп и файлы —
один комплект; скопированный live volume SQLite/Garage не заменяет экспорт объектов.
Перед удалением VPS скачать новую резервную копию с возникшими за показ чатами.
Выключение VM не прекращает оплату аренды; платные снимки также проверяются отдельно.
